# ADR-006 RAG 混合模式（嚴格引用 / 通用知識）

## 背景

初版採「嚴格 RAG」：只根據知識庫段落回答，無相關資料時回「知識庫中未找到相關資料」。
優點是絕不幻覺、有憑有據；缺點是空知識庫或不相關提問時體驗冷淡、無法回答。

## 決策

改為**混合模式**：

- 知識庫**有**相關資料 → 嚴格引用，標 `[來源 N]`
- 知識庫**無**相關資料 → 用 AI 通用知識回答，前綴標註「ℹ️ 此回答來自 AI 通用知識，非知識庫內容」

### 判斷邊界：相似度門檻

`match_chunks` RPC 永遠回傳最接近的 top-k 段落（無論相關與否），因此「檢索到 0 筆」無法作為切換依據。改用**相似度門檻** `SIMILARITY_THRESHOLD = 0.6`（`services/rag.py`）：

| 提問類型（實測 gemini-embedding-001 cosine）| 相似度 |
|------|--------|
| 切題（知識庫有此主題）| ~0.72–0.77 |
| 不切題（GDP/GNP、天氣）| ~0.49–0.51 |

0.6 為安全分界；低於門檻的段落全數濾除，交由通用模式回答。

## 後果

**優點**
- 空知識庫也能問答，體驗更完整
- disclaimer + 系統提示約束，來源清楚區分

**弊端與緩解**
- 幻覺風險回歸 → 通用模式提示禁止編造數據、要求提醒時效性、不加假 `[來源 N]`
- 判斷邊界仍為單一門檻，弱相關內容可能誤判 → 門檻可於 `rag.py` 調整
- 空知識庫提問不再短路，會多一次 LLM 呼叫（免費層需留意 15 RPM）

**實作**
- `services/llm.py` 拆出 `GROUNDED_SYSTEM_PROMPT` / `GENERAL_SYSTEM_PROMPT`，共用底層串流
- `routers/chat.py` 的無資料分支改呼叫 `stream_general` / `complete_general`

## 補充：檢索相關度外露（2026-07）

`match_chunks` 本就回傳每段落的 cosine 相似度（查詢↔段落關聯強度），原本只用於 0.6 門檻後丟棄。
改為將其轉百分比放進 sources data（`chat.py` `_sources_of` 的 `score`），前端在答案下方以條狀圖顯示
「引用來源（相關度）」，讓使用者看得到每個 `[來源 N]` 有多貼題、提升可信度透明度。

- 後端即算即回（DB 端 cosine），零額外 API；串流經 `sources` SSE 事件回傳
- 前端 `Message.sources`（`types.ts`）+ `MessageList` 條狀圖
